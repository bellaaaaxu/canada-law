## MCP 怎么接（D1c 之后的细化）

- **有官方文件位置的，直接合并编辑**：Claude 桌面版、Cursor、Codex（TOML）、Gemini CLI、Copilot CLI、Antigravity、Kiro、Qwen Code、OpenCode、Kimi Code。理由：可以先预览、可以精确撤销、可以用假目录测试。官方的「添加」命令大多没有对应的「删除」命令写在文档里
- **用官方命令**：Claude Code（`claude mcp add/remove`，它的配置文件里还存着应用状态，不宜手改）、VS Code（`code --add-mcp`，用户级配置文件位置没写明）
- **只装 skill、给手动说明**：Cline、DeepSeek Harness
- 所有写入：先备份成 `原文件名.bak-canada-law-时间`；已存在且相同就跳过；文件解析不了就不碰，改为提示手动添加
- 文件统一复制到 `~/.canada-law/`，各工具的配置指向那里；另存一份「装了什么」的记录，卸载和查看状态都靠它
- 不带 `--yes` 时只显示计划；在非交互环境（比如被 AI 调用）里也只显示计划，要求加 `--yes`

## 任务

2. **许可声明**：`get_section`、`get_toc`、`search_law` 的输出加 `notice` 字段（原文照搬）。先写测试
3. **ASCII JSON + 小程序 `cli.ts`**：五个命令、出错提示命令行也看得懂、退出码。先写测试（含「输出里没有非 ASCII 字节」）
4. **SKILL.md 定稿**：description ≤200 字符且写明「任何 BC 劳动法问题都用、别凭记忆」；全文 ASCII；Markdown 链接引用脚本；固定回答格式五部分；规则 1–7 + D1 新增两条。用测试检查这些格式要求
5. **MCP 单文件入口 + 打包脚本**：esbuild 生成三个单文件、加 shebang、复制术语表、打 `.mcpb`。冒烟测试：把产物复制到空目录运行（同 D1）
6. **安装器**：环境注入、14 个工具定义、JSON / TOML 合并与删除、计划、执行、卸载、状态。全部用假目录测：合并不破坏原有配置、重复安装不重复写、卸载只删我们的条目、解析失败不碰文件、非交互环境不带 `--yes` 不写
7. **golden 加英文三题**，经小程序和经 MCP 各跑一遍：6/6 在前 5
8. **package.json 改造**：`bin`、`files`、依赖全部改为开发依赖（产物已经自带）；`npm pack` 后从网址压缩包用 npx 跑安装器（拿掉 git，同 D1c）
